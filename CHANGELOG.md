## [0.7.0] - 2026-11-20

**Maintainer-path and tooling-map release.** This release moves the three patterns that govern changes to this library out of the path a consumer reads, deprecates their old paths, replaces private vocabulary with plain words, and adds a map of scanner and quality-gate tools with a rule for which tools the library names. No rule changes strength or scope.

**Change classes:** additive guidance (ADR 0060); navigation, editorial, and clarification (ADRs 0046 and 0047); deprecation (three old pattern paths); maintainer tooling. **Consumer impact:** no control changes. Links to the three old paths keep resolving; new work should cite the new paths. Hosts that pin verifier packs by version move to navigation pack 1.0.3. No skill priming block changed, so nothing is re-pinned by hash. **Migration:** each entry below carries its own note; none is needed to stay compliant. **Compatibility:** pre-1.0 minor, because it adds a tooling illustration and starts three deprecations; pin `v0.7.0` for this contract snapshot. No surface is removed, and each moved file leaves a pointer. The three files deprecated at `v0.5.0` remain, because this release is cut before their 90-day floor of 2026-12-14. Acceptance criteria 3, 4, 5, and 9 of the release plan are still unmet and retarget verbatim to `v0.8.0` (see the [plan note](doctrine/evolution/post-v0.3.0-external-review-decisions-and-v0.4.0-plan-2026-07.md)'s 2026-11-20 status update).

**Evidence:** ADRs 0046, 0047, and 0060 carry the changes, with the [scanner tooling research note](doctrine/evolution/research-scanner-tooling-map-2026-11.md). The [`v0.7.0` sweep follow-up](doctrine/evolution/sweep-2026-11.md#v070-release-coupled-follow-up-2026-11-20) re-read all 34 principle summaries, checked ADR and exception clocks, activated the three scheduled deprecations, requested all 626 external addresses cited in active doctrine, and took the first word-ratio reading under ADR 0047. The tagged revision passes doctrine preflight, contract and skill validation, tracked Markdown link validation, the unit tests, and style checks.

### Added

- **Scanner and quality-gate tooling map** ([ADR 0060](docs/adr/0060-name-only-open-source-gate-tools-usable-without-a-paid-plan.md)): a selection rule for the scanner and quality-gate tools the library names, and a new illustrative page, [Scanners And Quality Gates](doctrine/tooling/scanners-and-quality-gates.md). A tool is offered only if it is open source and runs on private, commercial code without a paid plan or licence key. Tools under Apache-2.0 or MIT are listed first, across ten language ecosystems; tools under other open-source licences are listed apart with the licence named; companions that need a paid plan are listed separately. The control suite page and the CI/CD delivery, testing and verification, Git hooks, dependency adoption, and infrastructure delivery references point to it. One listed tool is the maintainer's own; the page says so, as a disclosed exception to ADR 0027. Licences were read from 137 repositories on 2026-11-18 ([research note](doctrine/evolution/research-scanner-tooling-map-2026-11.md)). Change class: additive guidance; no obligation changes, so no migration.

### Changed

- **Maintainer patterns moved and vocabulary tidied** ([ADR 0046](docs/adr/0046-retire-private-vocabulary-where-a-standard-term-exists.md) and [ADR 0047](docs/adr/0047-separate-maintainer-doctrine-and-collapse-the-ai-native-sdlc.md), both amended and accepted on 2026-11-18). Three patterns that govern changes to this library moved from `doctrine/patterns/` to [`doctrine/maintainers/`](doctrine/maintainers/README.md): the change harness, the content lifecycle, and source grading. They remain patterns and bind only the people and agents changing the library. Each old path is a pointer, deprecated since `v0.7.0`. The two registers and the versioning pattern stay where they were; the versioning pattern's release notes minimum (§4) and maintainer checklist (§8) moved into the harness as §§9 and 10 and left pointers. "Estate-governed" is defined once, in the normative-language pattern §3. The glossary gains candidate, enactment, and estate-governed, and widens estate and materiality. Twenty uses of seven compounds that meant "set by the adopting organisation" now say so in plain words, and ten leftover uses of terms retired in September are replaced. The skills validator and the navigation verifier pack (now 1.0.3) count a path under `doctrine/maintainers/` as a pattern, each with a test that fails without the change. The collapse of the AI-native lifecycle pattern is withdrawn from ADR 0047 and needs its own ADR. **Change classes:** navigation; editorial; clarification; maintainer tooling. **Consumer impact:** no rule changes strength or scope. Links to the three old paths resolve through the pointers. No skill priming block changed, so nothing is re-pinned by hash. Schema edits are to descriptions only. A tool server that derives an entry's layer from its path needs one rule: files under `doctrine/maintainers/` are patterns. **Migration:** hosts that pin verifier packs by version move to navigation pack 1.0.3.
- **Tooling for maintainers:** the Cursor rule for library edits names the change harness at its new path, and `.gitignore` excludes local Codex agent state. Change class: maintainer tooling.

### Deprecated

- The old paths of the three maintainer patterns are deprecated since `v0.7.0` ([ADR 0047](docs/adr/0047-separate-maintainer-doctrine-and-collapse-the-ai-native-sdlc.md)): [patterns/doctrine-library-change-harness.md](doctrine/patterns/doctrine-library-change-harness.md), [patterns/doctrine-content-lifecycle.md](doctrine/patterns/doctrine-content-lifecycle.md), and [patterns/source-authority-and-evidence-grading.md](doctrine/patterns/source-authority-and-evidence-grading.md). Each points to the same file under [`doctrine/maintainers/`](doctrine/maintainers/README.md); cite the new path. Earliest exit: the first minor release cut at least 90 days after `v0.7.0`. Each path then stays as a tombstone that points forward ([register](doctrine/DEPRECATED.md)).

## [0.6.2] - 2026-11-18

Verifier-pack corrections, found by executing every pack check for the first time. **Change classes:** correction; maintainer tooling. **Consumer impact:** no control changes. Skill versions and block hashes are unchanged, so nothing is re-pinned by hash; four pack versions change. **Compatibility:** patch.

### Added

- `scripts/tests/test_skill_packs.py` runs every check in every shipped verifier pack against at least one input it should accept and one it should reject: 68 fixtures over 22 checks, in the existing unit-test step of CI. A check with no accepting or no rejecting fixture fails the suite. Until now nothing executed pack checks; `scripts/validate-skills.py` checks a pack's shape and the skill's block hash only. The [skills register](doctrine/skills/README.md) now asks for fixtures when a check is added.

### Fixed

- **Navigation pack 1.0.2:** `cited_files_not_deprecated` could never fail. It looked for a line starting `**Status: Deprecated`, a form no file carries. It now reads the first twelve lines of each cited file for a file-level banner in either form in use, the lifecycle template's `> **Status: Deprecated**` or the `> **Deprecated since …**` form the three deprecated files carry, and also recognises Retired, Superseded, and Rescinded. The template and the live banners still differ in wording; which is canonical is left open.
- **Citation pack 1.0.2:** `citations_carry_source_class` rejected class X as the skill's own priming block writes it (`[X C4, …]`). It now accepts X inside the bracketed tag.
- **Reading pack 1.0.2:** `exceptions_carry_expiry_and_authority` failed fatally on any use of the word "exception", including a runtime error. It now fires only when the word appears with a capitalised MUST or SHOULD, a doctrine path, a section number, or a word such as propose, grant, approve, expire, claim, obligation, or waiver. `evidence_state_named` now also catches stale evidence reported as a pass; absent and failed evidence stay with the reviewer, because an honest count of passes and failures would trip the same pattern.
- **Anti-confabulation pack 1.1.2:** `report_binds_candidate` passed on any seven-digit number, such as a date. A hex id now needs at least one letter a to f.

**Migration:** hosts that pin packs by version move to navigation, citation, and reading packs 1.0.2 and anti-confabulation pack 1.1.2. The method-record pack stays at 1.0.1. All five checks remain text approximations of a review judgement; the test fixes what each accepts and rejects, not whether a report is true.

## [0.6.0] - 2026-11-18

**Implementation-reference and rule-settlement release.** This release grows the implementation-reference layer from two references to sixteen, closes the owner gaps found while composing them, makes secretless workload identity the default, corrects and types the supply-chain evidence rules, and records a full review of the library with its corrections and the decisions the maintainer took from it.

**Change classes:** additive implementation guidance and navigation; normative tightening (ADRs 0051, 0053, 0059); normative additions, mostly at SHOULD (ADRs 0052, 0054, 0055, 0057, 0059); normative loosening (bot-only dependency updates in ADR 0052; hermetic builds in ADR 0053); normative correction and clarification (ADR 0058); an optional profile (ADR 0050); editorial and citation changes (ADR 0056); corrections. **Consumer impact:** some existing rules are stricter. Consumers who run production workloads on stored secrets, ship artefacts externally or into regulated environments, deploy by movable tag, or let agents initiate payments should read the entries for ADRs 0051, 0053, and 0059 before adopting. Other consumers gain guidance without new obligations. **Migration:** each normative entry below carries its own migration note. **Compatibility:** pre-1.0 minor with intentional normative movement; pin `v0.6.0` for this contract snapshot. No surface is removed or renamed; the adversarial-testing tiers are relabelled as risk classes. The three files deprecated at `v0.5.0` remain, because this release is cut before their 90-day floor of 2026-12-14. The plan's `v0.6.0` acceptance criteria were not all met: criteria 3, 4, 5, and 9 retarget verbatim to `v0.7.0` (see the [plan note](doctrine/evolution/post-v0.3.0-external-review-decisions-and-v0.4.0-plan-2026-07.md)'s 2026-11-18 status update).

**Evidence:** each structural or normative change has a carrying ADR and research note. The [`v0.6.0` release sweep](doctrine/evolution/sweep-2026-11.md) re-read all 34 principle summaries, checked ADR and exception clocks, requested every external source cited in active doctrine, and audited a sample of evidence grades. The [full review](doctrine/evolution/review-full-doctrine-2026-11.md) and its register record 360 findings; 22 decisions and 140 substance findings remain open. The tagged revision passes doctrine preflight, contract validation, tracked Markdown link validation, the unit tests, and style checks.
